§6.7

安全演算法選擇與安全模式命令程序

網路依營運商的優先順序挑演算法，再用 SMC 一來一回啟動保護，並重播 UE 安全能力來擋降級攻擊。

TS 33.501 Rel-18｜更新於 2026-11-08

看簡報版

為什麼需要

認證完成後，UE 和網路手上已經有金鑰，但還沒約好「要用哪一個演算法」，也還沒約好「從哪一則訊息開始保護」。這件事一定要雙方一致，否則一邊加密、另一邊卻不解密，訊息就全壞了。

麻煩在於：UE 是在還沒有安全保護的 Registration Request 裡回報自己支援哪些演算法（UE 安全能力）。中間人可以把強的演算法刪掉，誘使網路挑弱的、甚至挑不保護的空演算法，這叫降級攻擊（bidding down attack）。2G 的加密模式命令沒有完整性保護，就曾被這類攻擊利用。

5G 的解法是安全模式命令（Security Mode Command，SMC）：網路把「選好的演算法」和「UE 當初回報的安全能力」一起送回去，而且這則訊息有完整性保護，UE 一比對就知道有沒有被改過。4G（EPS）就已採用 NAS SMC 加 AS SMC 的設計，5G 沿用並分成兩層：UE 與 AMF 之間的 NAS SMC（§6.7.2），以及 UE 與基地台之間的 AS SMC（§6.7.4）。

運作流程

  1. UE在 Registration Request 中送出自己的 UE 安全能力。這則初始訊息此時還沒有 NAS 安全保護（見 NAS 安全那頁）。
  2. AMF主要認證完成後，從營運商設定的 NAS 加密、完整性兩份清單中，各挑優先順序最高的演算法（§6.7.1.1）。
  3. AMF先啟動 NAS 完整性保護，再送出 NAS Security Mode Command：必含重播的 UE 安全能力、選定的 NAS 演算法、ngKSI；可選擇帶 K_AMF_change_flag、要求完整初始 NAS 訊息的旗標、ABBA。送出後開始上行解密。
  4. UE驗證 SMC：比對重播的安全能力和自己存的是否一致，並用 ngKSI 指出的金鑰檢查完整性。通過就啟動 NAS 完整性與加解密；失敗則回 NAS Security Mode Reject。
  5. UE回傳加密且有完整性保護的 NAS Security Mode Complete。AMF 有要求時要附 PEI，也可以附上完整的初始 NAS 訊息。
  6. AMF解密並驗證 Complete 成功後，才開始下行加密。驗證成功也代表 UE 用的 SUPI 和 home network 給的一致。
  7. AMF要建立 AS 安全上下文時，把 UE 5G 安全能力送給 gNB／ng-eNB（§6.7.3.0）。
  8. gNB從自己的加密、完整性清單中，各挑「優先順序最高、且 UE 也支援」的演算法；選出的演算法同時用於 RRC 和 UP。
  9. gNB送出 AS Security Mode Command，內含選定的 RRC 與 UP 演算法，用目前 KgNB 推出的 RRC 完整性金鑰保護。送出後開始 RRC 下行加密。
  10. UE驗證 AS SMC 成功後開始下行解密，回傳有完整性保護的 AS Security Mode Complete，送出後開始上行加密。驗證失敗則回未受保護的 security mode failure。
  11. gNB驗證 Complete 成功後開始 RRC 上行解密。UP 的加密與完整性則依 SMF 給的 UP 安全政策另外啟用（§6.6.2）。

白話解釋

你要和公司總務處（AMF）約定以後公文用哪種鎖。你先寄一張「我家有哪些鎖」的清單，但這張是明信片，郵差可以偷偷把好鎖劃掉，讓總務處只能挑爛鎖。

所以總務處回信時，把你的清單原封不動抄一遍，連同「我們選這把鎖」一起寄回，信上還蓋了只有你們兩個才蓋得出來的印章。你核對抄回來的清單和自己寄出的一樣，就知道沒人動過手腳，從這封信開始雙方都上鎖；不一樣就拒絕。

進出大樓的門禁（基地台）要另外約一次鎖，這就是 AS SMC。管理員只能從總務處轉交的那份「你有哪些鎖」裡挑，不會聽信路人報的版本。

常見考點

  • NAS SMC 怎麼防降級攻擊？AMF 把 UE 在 Registration Request 送出的安全能力重播回 UE，且 SMC 有完整性保護。若中間人改過安全能力，UE 比對不一致就回 Reject，不會附著到網路（§6.7.2 NOTE 1）。
  • 為什麼 NAS SMC 只做完整性、不加密？UE 要先讀到選定的演算法和 ngKSI，才知道用哪把金鑰、哪個演算法；所以 Command 只能明文加完整性保護，UE 回的 Complete 才同時加密。
  • NAS 和 AS 演算法分別由誰選？NAS 由 AMF 選，AS 由 gNB／ng-eNB 選；兩者都依營運商設定的優先順序清單，加密與完整性各一份清單（§6.7.1.1、§6.7.3.0）。
  • NAS SMC 和 AS SMC 的網路端，誰先開始哪個方向？NAS：AMF 送出 Command 後先開上行解密，收到 Complete 才開下行加密。AS：gNB 送出 Command 後先開下行加密，驗證 Complete 才開上行解密。
  • AS SMC 什麼時候用？只在初始上下文建立，也就是 RRC_IDLE → RRC_CONNECTED、啟用新 KgNB 時；因為 KgNB 是新的，PDCP COUNT 可以歸零（§6.7.4）。
  • Xn 換手時演算法怎麼處理？來源基地台把 UE 安全能力和目前演算法放進 handover request，目標基地台自己重選，不同才寫進 Handover Command（ng-eNB 與 gNB 互換時一定要寫）。Path-Switch 時 AMF 比對安全能力，不一致就送回自己存的版本並記錄事件（§6.7.3.1）。
  • 從 RRC_INACTIVE 回到 RRC_CONNECTED，目標基地台不支援原演算法怎麼辦？改送 RRCSetup（SRB0），當成從 RRC_IDLE 重新建立連線，再透過 AS SMC 重新協商；若支援且沿用，則直接用原演算法保護 RRCResume（§6.7.3.4）。
  • 什麼情況會用 NIA0／NEA0？AMF 允許無法認證、處於 LSM 的 UE 建立緊急通話時，NAS 一律選 NIA0、NEA0，並只給基地台 EIA0、EEA0、NIA0、NEA0。除此之外，UE 不得接受 AS 完整性用空演算法（§6.7.3.6）。
