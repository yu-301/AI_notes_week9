§6.4

NAS 安全機制

UE 與 AMF 之間的 NAS 訊號同時有完整性與加密保護，並靠 NAS COUNT 防止重放攻擊。

TS 33.501 Rel-18｜更新於 2026-11-03

看簡報版

為什麼需要

非接取層（Non-Access Stratum，NAS）是 UE 和核心網路 AMF 之間的控制訊號，走 N1 參考點，負責註冊、移動管理、身分查詢，甚至 SMS over NAS。這些訊息會經過空中介面和基地台，攻擊者如果能竄改、偽造或重放它們，就能把手機的安全能力降級，或冒充網路下指令。

所以 NAS 訊息需要三種保護：完整性（訊息沒被改過、確實來自對方）、機密性（內容看不到）、重放保護（舊訊息不能再送一次）。保護的端點是 UE 和 AMF，基地台只負責轉送，看不到也改不了 NAS 內容（§6.4.1）。

4G 的 EPS 也有 NAS 安全，5G 沿用相同的 128-bit 演算法（Annex D）。5G 另外處理了兩件事：手機可同時從 3GPP 和非 3GPP 接取連上 AMF（§6.4.2），以及連「第一個」NAS 訊息也盡量保護（§6.4.6）。

關鍵名詞

KNASint / KNASenc NAS integrity key / NAS encryption key
由 KAMF 推出，分別只用於 NAS 完整性與 NAS 加密（見金鑰階層那頁）。
NIA / NEA Integrity Algorithm for 5G / Encryption Algorithm for 5G
5G 的完整性與加密演算法：128-NIA1～3、128-NEA1～3，和 4G 的 128-EIA／EEA1～3 相同；NIA0、NEA0 是不提供保護的空演算法（Annex D）。
NAS-MAC NAS Message Authentication Code
用 NIA 對 NAS 訊息算出的 32-bit 驗證碼，附在訊息後面；接收方重算比對。
NAS COUNT NAS Count
24-bit 計數器 = 16-bit NAS OVERFLOW + 8-bit NAS SQN；只有 NAS SQN 會放在訊息裡。上行、下行各一個。
NAS connection identifier NAS 連線識別碼
區分同一個 AMF 下的不同 NAS 連線：3GPP 接取為 0x01、非 3GPP 接取為 0x02，當作演算法的 BEARER 輸入。
NAS SMC NAS Security Mode Command
AMF 用來選定 NAS 演算法、啟動 NAS 安全的程序（§6.7.2）。

運作流程

  1. UE從 idle 狀態送出初始 NAS 訊息（例如 Registration Request）。沒有 NAS 安全上下文時，只放 cleartext IEs：SUCI 或 GUTI、UE 安全能力、ngKSI 等。
  2. UE如果已有 NAS 安全上下文，cleartext IEs 照樣明文，完整的初始訊息則加密放進 NAS container，整則訊息再做完整性保護。AMF 若持有相同上下文且驗證通過，可省略第 3～6 步。
  3. AMF找不到安全上下文，或完整性檢查失敗時，就對 UE 發起主要認證（§6.1.3）。
  4. AMF先啟動 NAS 完整性保護，再送出 NAS Security Mode Command：內含重播回來的 UE 安全能力、選定的 NAS 演算法與 ngKSI，只做完整性保護、不加密。送出後 AMF 開始對上行訊息解密。
  5. UE驗證 SMC 的完整性，並比對 UE 安全能力是否與自己當初送的一致。都通過就啟動 NAS 完整性與加密；失敗則回 Security Mode Reject。
  6. UE回傳加密且有完整性保護的 NAS Security Mode Complete。若 AMF 要求，或初始訊息原本沒有保護，就把完整的初始 NAS 訊息放在 NAS container 裡一起送。
  7. AMF驗證 Security Mode Complete 後開始下行加密，並以 container 中的完整初始訊息為準，回覆加密且有完整性保護的回應。
  8. UE / AMF之後每則 NAS 訊息都用 NAS COUNT 當輸入算 NAS-MAC 並加密。接收方每個 NAS COUNT 只接受一次，完整性檢查失敗的訊息原則上直接丟棄（§6.4.3.3）。

白話解釋

把 NAS 訊息想成你和總務處（AMF）之間的公文，中間由櫃台（基地台）轉交。每份公文都裝進只有你們倆打得開的信封（加密），封口蓋上專屬印章（NAS-MAC），信封上再寫流水號（NAS COUNT）。總務處看到重複的流水號就退件，所以有人把舊公文影印再送一次也沒用。

第一次來洽公時，信封外只寫你的代號和「我會用哪些鎖」，正式內容封在裡面。總務處回信時會把「你說你會用的鎖」再念一次給你聽，如果和你當初說的不一樣，就代表中間有人動過手腳。

常見考點

  • NAS 安全保護的是哪兩端？UE 與 AMF（N1 參考點）。基地台只轉送 NAS 訊息；UE 與 gNB 之間的 RRC、UP 是另外的 AS 安全（§6.5、§6.6）。
  • NAS COUNT 由什麼組成？24 bits = 16-bit NAS OVERFLOW + 8-bit NAS SQN，只有 NAS SQN 會隨訊息傳送。送進演算法時前面補 0x00 成 32-bit COUNT（§6.4.3.1）。
  • 為什麼 NAS COUNT 不能隨便歸零？同一把 KAMF 下若歸零，相同的金鑰配上相同的 COUNT 會讓金鑰流重複使用，例如 UE 在兩個 AMF 之間來回、又推出同一組 NAS 金鑰時。所以只有產生新的 KAMF 時，NAS COUNT 才從 0 開始（§6.4.5）。
  • UE 同時從 3GPP 和非 3GPP 連到同一個 AMF 時怎麼辦？兩條連線共用一個 NAS 安全上下文（金鑰、演算法），但各有自己的 NAS connection identifier（0x01／0x02）和一組上下行 NAS COUNT。如果連到不同 PLMN，則維護兩套獨立的上下文（§6.4.2）。
  • 初始 NAS 訊息怎麼保護？沒有安全上下文時只送 cleartext IEs；有的話，完整訊息加密放進 NAS container，整則做完整性保護（§6.4.6）。
  • NAS SMC 怎麼防降級攻擊？SMC 把 UE 在 Registration Request 中送出的安全能力重播給 UE。攻擊者若竄改過，UE 比對時就會發現，驗證失敗（§6.7.2）。
  • 完整性保護啟用後可以改回 NULL 嗎？不行。NAS 完整性一旦啟用，就一直有效到安全上下文被刪除，不能從非 NULL 演算法換成 NULL；選 NIA0 時也不會啟用重放保護（§6.4.3.2）。
