§6.12

SUPI 隱藏與 SUCI

5G 用公鑰加密把用戶永久身分 SUPI 包成 SUCI，空中介面上不再出現明文 IMSI，讓假基地台抓不到你是誰。

TS 33.501 Rel-18｜更新於 2026-11-03

看簡報版

為什麼需要

在 2G 到 4G，當網路認不出手機的臨時身分時，會要求手機回傳 IMSI，而手機會用明文送出。攻擊者只要架一台假基地台（IMSI catcher），主動發出身分請求，就能拿到附近每支手機的 IMSI，進而追蹤特定使用者的位置。

5G 的目標是：永久身分不再以明文出現在空中介面。做法是讓手機用 home network 的公鑰加密身分，只有 home network 能解開。

關鍵名詞

SUPI Subscription Permanent Identifier
用戶永久身分，最常見的格式就是 IMSI。等同你的「身分證字號」，不應外洩。
SUCI Subscription Concealed Identifier
SUPI 加密後的版本，可以安全地在空中介面傳送。
5G-GUTI 5G Globally Unique Temporary Identifier
網路分配的臨時身分。認證完成後，平常的通訊大多用它，而不是 SUCI。
SIDF Subscription Identifier De-concealing Function
位在 home network 的 UDM 裡，持有私鑰，負責把 SUCI 解回 SUPI。
ECIES Elliptic Curve Integrated Encryption Scheme
橢圓曲線混合加密：先用 ECDH 算出共享金鑰，再用對稱加密保護資料。SUCI 就是用它產生的。

運作流程

  1. 電信業者（事前配置）把 home network 公鑰和公鑰 ID 寫進 USIM，私鑰則只存在 home network 的 SIDF。
  2. UE每次需要送出身分時，都產生一組全新的臨時（ephemeral）金鑰對。
  3. UE用臨時私鑰和 home network 公鑰做 ECDH 得到共享祕密，再經 KDF 推導出加密金鑰與 MAC 金鑰。
  4. UE只加密 SUPI 中的 MSIN，並附上 MAC tag；MCC/MNC 保持明文，組成 SUCI 送出。
  5. AMF/SEAF → AUSF → UDM服務網路看不懂 SUCI，只依明文的 MCC/MNC 把它隨認證請求轉送回 home network。
  6. UDM 中的 SIDF用私鑰重算共享祕密，驗證 MAC 後解出 SUPI，接著進行認證。
  7. 認證成功後服務網路才取得 SUPI，並分配 5G-GUTI；之後的通訊改用 5G-GUTI。

白話解釋

想像你寄一封信。信封外面只寫「請轉交台北總局」，讓沿途郵差知道該往哪送；收件人姓名則封在一個只有台北總局能打開的內袋裡。

而且你每次寄信都用全新的內袋，所以就算有人攔下你寄的兩封信，也看不出是同一個人寄的。這就是 SUCI：MCC/MNC 是信封外的地址，加密的 MSIN 是內袋，臨時金鑰讓每個內袋都不一樣。

常見考點

  • 為什麼 MCC/MNC 不加密？服務網路需要知道要把請求轉給哪一家 home network，才能讓 SIDF 解密；如果全部加密，就沒人知道要送去哪裡。
  • 為什麼同一支手機每次送出的 SUCI 都不一樣？因為每次都用新的臨時金鑰對，密文因此不同，攻擊者無法把多次出現的 SUCI 連結到同一人（unlinkability）。
  • 誰能把 SUCI 解回 SUPI？只有 home network UDM 裡的 SIDF，因為私鑰只在那裡；漫遊時的服務網路解不開。
  • SUCI 由誰計算？可以在 USIM 內計算，也可以由手機（ME）計算，由 home network 業者決定。
  • 什麼情況會使用 null scheme？有什麼風險？例如 home network 沒有配置公鑰，或未經認證的緊急通話。此時 SUPI 等同明文送出，失去隱私保護。
  • SUPI、SUCI、5G-GUTI 差在哪？SUPI 是永久身分；SUCI 是它加密後的版本，主要用在初次註冊；5G-GUTI 是認證後網路分配的臨時身分，用在日常通訊。
