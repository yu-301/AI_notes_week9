§6.2

5G 金鑰階層與金鑰推導

從長期金鑰 K 一層層推導出 NAS、RRC、UP 各自的金鑰，每一層只交給需要它的網元。

TS 33.501 Rel-18｜更新於 2026-11-03

看簡報版

為什麼需要

認證完成後，手機要和很多網元建立安全通道：和 AMF 保護 NAS 訊息、和基地台保護 RRC 訊息與使用者資料。如果大家共用同一把金鑰，只要其中一個網元（例如放在路邊的基地台）被攻破，所有通道都會一起失守，長期金鑰也可能跟著外洩。

解法是金鑰分離：長期金鑰 K 只留在 USIM 和 home network 的 ARPF，其他金鑰都用單向的金鑰推導函數（Key Derivation Function，KDF）一層層往下推，每一層只交給需要它的網元。拿到下層金鑰，推不回上層金鑰。

4G 也有類似的階層，核心是 KASME。5G 在上面多加了 KAUSF 和 KSEAF 兩層：home network 自己保留 KAUSF，服務網路拿到的錨點金鑰 KSEAF 綁定服務網路名稱，而且和 4G 的 KASME 在密碼學上是分開的（§6.1.1.3）。

關鍵名詞

K Long-term Key
USIM 和 ARPF 共享的長期金鑰，長度 128 或 256 bits；只在 ARPF 的安全環境裡處理（§6.2.2.1）。
KDF Key Derivation Function
單向的金鑰推導函數。5GC 的所有推導都用 TS 33.220 Annex B.2.0 定義的 KDF，每種用途用不同的 FC 值區分（Annex A.1）。
KAUSF / KSEAF Key for AUSF / Key for SEAF
KAUSF 留在 home network 的 AUSF；KSEAF 是由它推出、交給服務網路的錨點金鑰（anchor key）。
KAMF Key for AMF
AMF 手上的根金鑰，NAS 金鑰、KgNB、KN3IWF 都從它推出。
KNASint / KNASenc NAS integrity key / NAS encryption key
保護 UE 與 AMF 之間 NAS 訊號的完整性金鑰與加密金鑰。
KgNB Key for gNB
基地台的根金鑰，RRC 與 UP 金鑰都從它推出；ng-eNB 把它當成 KeNB 使用。
KRRCint / KRRCenc / KUPint / KUPenc RRC / UP integrity and encryption keys
保護 UE 與 gNB 之間 RRC 訊號和使用者資料（UP）的金鑰。
NH Next Hop
由 AMF 推出的中間金鑰，換手時用來產生新的 KgNB，提供前向安全（forward security）。
KN3IWF Key for N3IWF
非 3GPP 接取用的金鑰，N3IWF 把它當作和 UE 跑 IKEv2 的 MSK。
ngKSI Key Set Identifier in 5G
KAMF 的編號，讓 UE 和 AMF 不必重新認證就能指認同一組安全上下文（§6.2.3.2）。

運作流程

  1. ARPF / USIM雙方各自保存同一把 K。認證時由 K 產生 CK、IK；若用 EAP-AKA'，ARPF 再把它們轉成 CK'、IK'。
  2. ARPF 或 AUSF5G-AKA 由 ARPF 推出 KAUSF，放在 5G HE AV 裡交給 AUSF；EAP-AKA' 則由 AUSF 從 CK'、IK' 推出。AUSF 可依業者政策保存最新的 KAUSF。
  3. AUSF由 KAUSF 推出錨點金鑰 KSEAF，認證成功後交給服務網路的 SEAF。
  4. SEAF認證一結束就由 KSEAF 推出 KAMF 交給 AMF，接著刪除 KSEAF。KSEAF 永遠不會傳出 SEAF。
  5. AMF由 KAMF 推出 KNASint、KNASenc，透過 NAS Security Mode Command 啟用（§6.7.2）。
  6. AMF由 KAMF 與 uplink NAS COUNT 推出 KgNB（3GPP 接取）或 KN3IWF（非 3GPP 接取）。KgNB 和 NH（附上 NCC）交給 gNB，KN3IWF 交給 N3IWF。
  7. gNB由 KgNB 推出 KRRCint、KRRCenc、KUPint、KUPenc，透過 AS Security Mode Command 啟用（§6.7.4）。
  8. UE（USIM + ME）網路端的每一把金鑰，UE 都有對應的一把：USIM 由 K 產生 CK、IK，ME 推出其餘所有金鑰。USIM 支援 5G 參數儲存時，KAUSF、KSEAF、KAMF 存在 USIM，否則存在 ME 的非揮發性記憶體。

白話解釋

想像一棟大樓的鑰匙系統。總鑰匙（K）鎖在總公司保險箱和你的 SIM 卡裡，從不外借。總公司用它刻出一把總公司鑰匙（KAUSF），再刻一把分公司大門鑰匙（KSEAF、KAMF）交給分公司。

分公司再替各部門刻專用門卡：NAS 一張、基地台一張（KgNB），基地台又替 RRC 和使用者資料各刻加密卡與驗證卡。刻鑰匙的方法是單向的，撿到部門門卡也刻不回大門鑰匙，所以一個部門出事不會連累整棟樓。

常見考點

  • 為什麼要分這麼多層金鑰？金鑰分離：KDF 是單向的，下層金鑰外洩推不回上層，不同用途也互不影響。長期金鑰 K 只在 USIM 和 ARPF，服務網路只拿得到 KSEAF 以下的金鑰。
  • KAUSF 在 5G-AKA 和 EAP-AKA' 中由誰推導？5G-AKA 由 ARPF 從 CK、IK 推導後交給 AUSF；EAP-AKA' 由 AUSF 從 CK'、IK' 推導。UE 端都由 ME 推導（§6.2.1）。
  • SEAF 怎麼處理 KSEAF？只在 SEAF 內使用、不傳給任何其他實體；推出 KAMF 後就刪除。每次認證都會產生新的 KSEAF 和 KAMF（§6.2.2.1）。
  • 同一把 KAMF 怎麼推出兩把不同的 NAS 金鑰？輸入不同的演算法類型區分值（N-NAS-enc-alg 為 0x01、N-NAS-int-alg 為 0x02）和演算法 ID，再取輸出的低位元當金鑰（Annex A.8）。
  • KgNB 和 KN3IWF 的推導差在哪？用同一個函數（Annex A.9），輸入都是 KAMF 和 uplink NAS COUNT，只差在接取類型區分值：3GPP 為 0x01、非 3GPP 為 0x02。
  • ngKSI 是什麼？值為 '111' 代表什麼？ngKSI 是 KAMF 的識別碼，分 native 和 mapped 兩種，值有 3 bits。'111' 保留給 UE 表示「沒有可用的 KAMF」，網路收到後可以重新認證（§6.2.3.2、§6.2.3.3）。
  • KAMF 什麼時候會重新產生？主要認證、NAS 金鑰 re-keying、NAS 金鑰 refresh，以及與 EPS 互通的程序（§6.2.3.3）。
