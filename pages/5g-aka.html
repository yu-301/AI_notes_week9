§6.1.3.2

5G-AKA 認證

手機與網路用 USIM 裡的長期金鑰互相認證，最後由 home network 親自確認結果，拜訪網路無法自行宣稱認證成功。

TS 33.501 Rel-18｜更新於 2026-11-03

看簡報版

為什麼需要

手機連上網路前，雙方都要確認對方是真的：網路要確認這張 SIM 卡是合法用戶，手機也要確認自己不是連到假基地台。這就是認證與金鑰協商（Authentication and Key Agreement，AKA）要做的事，同時還要產生後續加密用的金鑰。

4G 的 EPS-AKA 有一個缺點：home network 把認證向量交給拜訪網路（MME）後，比對結果完全由拜訪網路決定，home network 不會知道手機是否真的有出現。漫遊時，惡意或出錯的拜訪網路可以宣稱「用戶已認證」，藉此冒用身分或灌水帳單。

5G-AKA 的改進是增加 home network 的控制（increased home control）：拜訪網路只能先做初步檢查，最終要把手機的回應送回 home network 的 AUSF 比對，確認成功後才交出金鑰。

關鍵名詞

5G-AKA 5G Authentication and Key Agreement
5G 的主要認證方法之一（另一個是 EAP-AKA'），基於 USIM 與 home network 共享的長期金鑰 K。
SEAF Security Anchor Function
位在服務網路的 AMF 裡，負責向手機發出認證請求、做初步比對，並保管 KSEAF。
AUSF Authentication Server Function
位在 home network，負責最終比對手機回應，並把 KSEAF 交給 SEAF。
ARPF Authentication credential Repository and Processing Function
位在 UDM 裡，保存長期金鑰 K，負責產生認證向量。
RAND / AUTN Random Challenge / Authentication Token
RAND 是網路出的隨機題目；AUTN 讓 USIM 驗證「題目確實來自 home network，而且不是舊的」。
RES* / XRES* Response / Expected Response
RES* 是手機算出的答案；XRES* 是 home network 事先算好的標準答案。
HRES* / HXRES* Hash of RES* / Hash of XRES*
上面兩者的雜湊值，讓 SEAF 能初步比對答案，卻拿不到標準答案本身。
KAUSF / KSEAF Key for AUSF / Key for SEAF
由 CK、IK 推導出的金鑰；KSEAF 是服務網路的錨點金鑰，再往下推導出 KAMF。

運作流程

  1. SEAF手機要註冊時，SEAF 向 AUSF 發起認證，帶上 SUCI（或 SUPI）與服務網路名稱（SN name）。
  2. AUSF確認這個 SEAF 有權使用該 SN name，再把請求轉給 UDM/ARPF。
  3. UDM/ARPF若收到 SUCI 就先由 SIDF 解出 SUPI，選擇 5G-AKA 後產生 5G HE AV（RAND、AUTN、XRES*、KAUSF）回給 AUSF。
  4. AUSF保存 XRES*，從 KAUSF 推出 KSEAF、從 XRES* 算出 HXRES*；只把 5G SE AV（RAND、AUTN、HXRES*）交給 SEAF。
  5. SEAF透過 NAS Authentication Request 把 RAND、AUTN、ngKSI、ABBA 送給手機。
  6. UE（USIM + ME）USIM 驗證 AUTN 確認網路真偽與新鮮度，並算出 RES、CK、IK；ME 再由 RES 推出 RES*，並推導 KAUSF、KSEAF。
  7. SEAF收到 RES* 後算出 HRES* 與 HXRES* 比對，相符就代表服務網路端認證成功，接著把 RES* 轉給 AUSF。
  8. AUSF比對 RES* 與 XRES*，相符就代表 home network 端認證成功，把 KSEAF（若一開始用 SUCI，也附上 SUPI）交給 SEAF，SEAF 再推導出 KAMF。

白話解釋

想像你出國去分公司辦事，分公司要確認你是本人。總公司寄給分公司一道考題，以及「標準答案的指紋」，但不給標準答案本身。你答完題，分公司先比對指紋，覺得沒問題，再把你的答案送回總公司。

總公司親自對過標準答案，確定是你本人，才把分公司的門禁卡（KSEAF）交出去。這樣分公司就算想謊稱「他來過了」，沒有你的真實答案也騙不了總公司。

常見考點

  • 5G-AKA 和 4G EPS-AKA 最大的差別？增加 home network 控制：最終比對由 home network 的 AUSF 完成，拜訪網路不能自行宣稱認證成功。
  • 為什麼 SEAF 只拿到 HXRES*，不直接拿 XRES*？讓 SEAF 能先初步檢查手機的答案，但它不知道標準答案，所以無法偽造 RES* 去騙 AUSF。
  • 手機怎麼確認網路是真的？USIM 用長期金鑰 K 驗證 AUTN 中的 MAC，確認題目來自 home network；再檢查 SQN 確認不是重放的舊題目，因此是雙向認證。
  • 服務網路名稱（SN name）有什麼用？它被放進 RES*、KAUSF 的推導中，使答案和金鑰只對這個服務網路有效，換一個網路就不能沿用。
  • USIM 發現 SQN 不同步怎麼辦？手機回傳 Authentication Failure 並附上 AUTS，由 home network 重新同步 SQN 後再認證（§6.1.3.3）。
  • AUSF 確認成功後還要做什麼？通知 UDM 認證結果，讓 home network 之後能把這次認證與後續程序連結起來 待查證：§6.1.4。
