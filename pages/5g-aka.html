§6.1.3.2

5G-AKA 認證

手機與網路用 USIM 裡的長期金鑰互相認證，最後由 home network 親自確認結果，拜訪網路無法自行宣稱認證成功。

TS 33.501 Rel-18｜更新於 2026-11-03

看簡報版

為什麼需要

手機連上網路前，雙方都要確認對方是真的：網路要確認這張 SIM 卡是合法用戶，手機也要確認自己不是連到假基地台。這就是認證與金鑰協商（Authentication and Key Agreement，AKA）要做的事，同時還要產生後續加密用的金鑰。

4G 的 EPS-AKA 有一個缺點：home network 把認證向量交給拜訪網路（MME）後，比對結果完全由拜訪網路決定，home network 拿不到「手機真的有出現並通過認證」的證據。這會讓某些詐騙有機可乘，例如替根本不在該網路的用戶，向 home network 登記服務中的 AMF（§6.1.4.1 舉的例子是偽造的 Nudm_UECM_Registration Request）。

5G-AKA 的改進是增加 home network 的控制（increased home control）：拜訪網路要把手機的回應 RES* 當作認證確認（Authentication Confirmation）送回 home network 的 AUSF，作為認證成功的證明；AUSF 確認後才交出金鑰（§6.1.3.2.0）。

關鍵名詞

5G-AKA 5G Authentication and Key Agreement
5G 的主要認證方法之一（另一個是 EAP-AKA'），基於 USIM 與 home network 共享的長期金鑰 K。
SEAF Security Anchor Function
位在服務網路的 AMF 裡，負責向手機發出認證請求、做初步比對，並保管 KSEAF。
AUSF Authentication Server Function
位在 home network，負責最終比對手機回應、把結果通知 UDM，並把 KSEAF 交給 SEAF。
ARPF Authentication credential Repository and Processing Function
位在 UDM 裡，保存長期金鑰 K，負責產生認證向量。
RAND / AUTN Random Challenge / Authentication Token
RAND 是網路出的隨機題目；AUTN 讓 USIM 驗證「題目確實來自 home network，而且不是舊的」。
RES* / XRES* Response / Expected Response
RES* 是手機由 RES、RAND 與服務網路名稱算出的答案；XRES* 是 home network 用同樣方式事先算好的標準答案（Annex A.4）。
HRES* / HXRES* Hash of RES* / Hash of XRES*
把 RAND 和 (X)RES* 接起來做 SHA-256 取 128 bits（Annex A.5），讓 SEAF 能初步比對答案，卻拿不到標準答案本身。
KAUSF / KSEAF Key for AUSF / Key for SEAF
KAUSF 由 CK||IK 與服務網路名稱推導（Annex A.2）；KSEAF 再由 KAUSF 推導（Annex A.6），是服務網路的錨點金鑰，往下推出 KAMF。

運作流程

  1. SEAF向 AUSF 送出 Nausf_UEAuthentication_Authenticate Request，帶上 SUCI（持有有效 5G-GUTI 的重新認證則用 SUPI）與服務網路名稱（SN name）。
  2. AUSF確認這個 SEAF 有權使用該 SN name，不符就回覆「serving network not authorized」；通過後把請求轉給 UDM/ARPF。
  3. UDM/ARPF若收到 SUCI 就先由 SIDF 解出 SUPI，再依 SUPI 選擇認證方法。選了 5G-AKA 就產生 AMF separation bit 為 1 的認證向量，組成 5G HE AV（RAND、AUTN、XRES*、KAUSF）回給 AUSF。
  4. AUSF暫存 XRES*（連同 SUCI 或 SUPI），算出 HXRES* 與 KSEAF；接著拿掉 KSEAF，只把 5G SE AV（RAND、AUTN、HXRES*）交給 SEAF。
  5. SEAF透過 NAS Authentication Request 把 RAND、AUTN、ngKSI、ABBA 送給手機。
  6. UE（USIM + ME）USIM 驗證 AUTN 確認網路真偽與新鮮度，算出 RES、CK、IK；ME 再算出 RES*、KAUSF、KSEAF，並檢查 AUTN 裡的 separation bit 是否為 1，最後以 Authentication Response 回傳 RES*。
  7. SEAF算出 HRES* 與 HXRES* 比對，相符就代表從服務網路的角度認證成功。不論結果如何，SEAF 都會把 RES* 轉給 AUSF 作為認證確認（§6.1.3.2.2）。
  8. AUSF比對 RES* 與 XRES*（也可以檢查 5G AV 是否過期），相符就代表從 home network 的角度認證成功，並把結果通知 UDM。成功時才把 KSEAF（若一開始用 SUCI，也附上 SUPI）交給 SEAF。
  9. SEAF / AMFSEAF 由 KSEAF、ABBA 與 SUPI 推導出 KAMF 交給 AMF，AMF 接著啟動 NAS Security Mode Command（§6.7.2）。UE 收到合法的 Security Mode Command，才認定這次認證成功。

白話解釋

想像你出國去分公司辦事，分公司要確認你是本人。總公司寄給分公司一道考題，以及「標準答案的指紋」，但不給標準答案本身。你答完題，分公司先比對指紋，再把你的答案送回總公司。

總公司親自對過標準答案，確定是你本人，才把分公司的門禁卡（KSEAF）交出去，還會記下「你哪天在哪間分公司通過驗證」。這樣分公司就算想謊稱「他來過了」，沒有你的真實答案也騙不了總公司。

常見考點

  • 5G-AKA 和 4G EPS-AKA 最大的差別？增加 home network 控制：拜訪網路要把 RES* 送回 home network 當作認證確認，由 AUSF 做最終比對，拜訪網路不能自行宣稱認證成功。
  • 為什麼 SEAF 只拿到 HXRES*，不直接拿 XRES*？讓 SEAF 能先初步檢查手機的答案，但它不知道標準答案，所以無法偽造 RES* 去騙 AUSF。
  • 手機怎麼確認網路是真的？USIM 用長期金鑰 K 驗證 AUTN 中的 MAC，確認題目來自 home network；再檢查 SQN 確認不是重放的舊題目，因此是雙向認證。
  • 服務網路名稱（SN name）有什麼用？SN name 是「5G:」加上 SN Id，被放進 RES*、KAUSF、KSEAF 的推導。答案和金鑰因此只對這個服務網路有效，一個服務網路也無法冒充另一個（隱含的服務網路認證，§6.1.1.3）。
  • USIM 發現 SQN 不同步怎麼辦？手機回 Authentication Failure 並附上 USIM 給的 AUTS。SEAF 把 RAND、AUTS 和 synchronisation failure indication 經 AUSF 送到 UDM/ARPF，重新同步後產生新向量再認證（§6.1.3.3）。
  • RES* 比對失敗怎麼辦？如果手機一開始用 SUCI，SEAF 就回 Authentication Reject；如果用 5G-GUTI，SEAF/AMF 改發 Identification 程序要求 SUCI，可以再試一次認證（§6.1.3.2.2）。
  • AUSF 確認成功後還要做什麼？用 Nudm_UEAuthentication_ResultConfirmation 通知 UDM（含 SUPI、時間戳記、認證類型、SN name）。UDM 記下後，之後收到 AMF 的 Nudm_UECM_Registration 時，就能檢查這個用戶是否真的認證過（§6.1.4.1a）。
