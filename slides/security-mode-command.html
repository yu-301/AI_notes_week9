§6.7

安全演算法選擇與安全模式命令程序

網路依營運商的優先順序挑演算法，再用 SMC 一來一回啟動保護，並重播 UE 安全能力來擋降級攻擊。

為什麼需要

  • 有了金鑰，雙方還得約好用哪個演算法、從哪則訊息開始保護
  • UE 安全能力在未保護的 Registration Request 中送出，可能被竄改
  • 中間人刪掉強演算法 → 降級攻擊（2G 曾受害）
  • SMC 重播安全能力並加完整性保護；分 NAS SMC 與 AS SMC 兩層

運作流程（1/3）：NAS SMC

  1. UERegistration Request 送出 UE 安全能力（尚未保護）
  2. AMF認證後依清單各挑優先順序最高的 NAS 演算法
  3. AMF送 NAS SMC：重播安全能力、選定演算法、ngKSI；送出後開上行解密
  4. UE比對安全能力、驗證完整性；通過就啟動 NAS 保護，失敗回 Reject

運作流程（2/3）：完成 NAS、轉交 AS

  1. UE回加密 + 完整性的 Complete，可附 PEI、完整初始訊息
  2. AMF驗證 Complete 後開始下行加密
  3. AMF把 UE 5G 安全能力交給 gNB
  4. gNB挑清單最優先、UE 也支援的演算法（RRC 與 UP 共用）

運作流程（3/3）：AS SMC

  1. gNB送 AS SMC（KgNB 推出的 RRC 完整性金鑰），送出後開下行加密
  2. UE驗證後開下行解密，回 Complete，送出後開上行加密
  3. gNB驗證 Complete 後開上行解密；UP 依 UP 安全政策啟用

白話解釋

你用明信片告訴總務處（AMF）你有哪些鎖，郵差可能偷改。總務處回信時把清單原樣抄回，加上「選這把」並蓋專屬印章；你核對一致才開始上鎖。

大樓門禁（基地台）要另外約一次鎖（AS SMC），且只能從總務處轉交的清單裡挑。

常見考點（1/3）

  • NAS SMC 怎麼防降級？重播 UE 安全能力 + 完整性保護，UE 比對不符就 Reject
  • 為什麼 NAS SMC 不加密？UE 要先讀到演算法和 ngKSI 才知道怎麼解
  • 演算法由誰選？NAS 由 AMF、AS 由 gNB，都依營運商優先順序清單

常見考點（2/3）

  • 網路端先開哪個方向？NAS 先開上行解密；AS 先開下行加密
  • AS SMC 何時用？只在 RRC_IDLE → CONNECTED、新 KgNB 時，PDCP COUNT 可歸零
  • Xn 換手？目標基地台重選，不同才寫進 Handover Command；AMF 在 Path-Switch 比對安全能力

常見考點（3/3）

  • INACTIVE → CONNECTED 不支援原演算法？送 RRCSetup 回退，再走 AS SMC
  • 何時用 NIA0／NEA0？LSM 下未認證 UE 的緊急通話；其他情況 UE 不接受 AS 空完整性
