§6.9

換手時的安全處理與金鑰推導

換手時從目前金鑰（水平）或 AMF 的 NH（垂直）推出新金鑰，靠 NCC 同步；垂直推導讓舊基地台算不出新金鑰。

為什麼需要

  • 換基地台時要決定新 KgNB，又不能每次重新認證
  • 新舊共用金鑰：攻破一台，之後經過的基地台全曝光
  • 目標：舊基地台算不出新金鑰 → 前向安全
  • 5G 換手會同步 NAS 與 AS 上下文，這點與 4G（EPS）不同

關鍵名詞

KNG-RAN* Key for target NG-RAN node
換手後的新 KgNB
NH Next Hop
只有 UE、AMF 算得出的鏈
NCC Next hop Chaining Counter
NH 鏈的編號
水平推導 Horizontal key derivation
從目前 KgNB 推
垂直推導 Vertical key derivation
從 AMF 給的 NH 推

水平 vs 垂直金鑰推導

項目水平垂直
從哪推目前 KgNB未使用的 NH
原料來源來源基地台自己有AMF 提供
NCC不變變大，UE 追算 NH
何時用沒有未使用的 {NH, NCC}有未使用的 NH；N2 一律由 AMF 給新 NH
都要綁定目標 PCI 與 ARFCN-DL
前向安全沒有有

三種換手的比較

類型誰算 KNG-RAN*新 {NH, NCC} 來源
Intra-gNB-CU同一 gNB，可依政策保留有 NH 就垂直，否則水平
Xn來源基地台Path Switch Ack，留給下次用
N2目標基地台AMF 收到 HANDOVER REQUIRED 就算

運作流程（1/3）：初始與 Xn 換手

  1. AMF / UE推出 KgNB（NCC=0）與 NH（NCC=1）；AMF 不把 NH 給 gNB
  2. 來源 gNB有未使用 NH 就垂直，否則水平，綁 PCI、ARFCN-DL
  3. 來源 → 目標 gNB交出 {KNG-RAN*, NCC}，NCC 放進 HO Command
  4. UENCC 相同做水平；不同就追算 NH 後做垂直

運作流程（2/3）：Path Switch 與 N2

  1. AMFPath Switch 時 NCC+1、算新 NH 給目標基地台，留給下次
  2. 來源 AMFN2：收到 HANDOVER REQUIRED 就算新 NH，可選水平 KAMF 推導
  3. 目標 AMFKAMF 或演算法有變，就建立帶 NAS MAC 的 NASC

運作流程（3/3）：N2 收尾

  1. 目標 gNB用 NH + PCI、ARFCN-DL 算新 KgNB，NCC 與 NASC 放進 HO Command
  2. UE驗證 NASC；旗標為 1 就換新 KAMF，失敗就中止換手

白話解釋

水平推導像櫃台用你現在的房卡加新房號直接做新卡：很快，但舊櫃台也做得出來。

垂直推導像總公司（AMF）先寄新母卡（NH）給下一間分館，舊分館沒看過母卡就進不了你的新房間；NCC 是母卡的流水號。

常見考點（1/3）

  • 水平與垂直差在哪？水平用目前 KgNB、無前向安全；垂直用 NH、有前向安全
  • 第一次 Xn 換手為何是水平？初始建立時 AMF 不給 NH
  • Xn 為何兩跳才有前向安全？新 NH 在 Path Switch Ack 才到，只能下次用

常見考點（2/3）

  • N2 換手呢？AMF 先算新 NH 直接給目標，來源基地台拿不到
  • UE 怎麼選？比對 NCC：相同水平，不同追算 NH 後垂直
  • 水平 KAMF 推導 = AS 水平推導？不是；前者在 NAS 層換 KAMF

常見考點（3/3）

  • NASC 的 COUNT 為何用 232−1？不在正常範圍，避免重複
  • 何時可不換 KgNB？只有 intra-gNB-CU 換手，依 gNB 政策
  • 移動註冊更新怎麼換 KAMF？來源 AMF 水平推導，目標 AMF 用 NAS SMC 帶旗標
