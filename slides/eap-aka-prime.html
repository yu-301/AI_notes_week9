§6.1.3.1

EAP-AKA' 認證

把 AKA 包進 EAP 框架：SEAF 只轉送，由 home network 的 AUSF 當 EAP 伺服器驗證。

為什麼需要

  • 5G 希望 3GPP 與非 3GPP 接取都用同一套認證框架
  • 4G：EAP-AKA' 主要用在可信任的非 3GPP 接取
  • 5G：UE 與服務網路必須同時支援 EAP-AKA' 和 5G-AKA，由業者選
  • AUSF 親自當 EAP 伺服器，同樣具備 increased home control

關鍵名詞

EAP Extensible Authentication Protocol
承載各種認證方法的框架
EAP-AKA' Improved Extensible Authentication Protocol Method for 3rd Generation Authentication and Key Agreement
在 EAP 裡執行的 AKA
AV' Transformed Authentication Vector
RAND、AUTN、XRES、CK'、IK'
CK' / IK' Cipher Key prime / Integrity Key prime
CK、IK 加入 SN name 推導
EMSK Extended Master Session Key
取最高 256 bits 當 KAUSF

運作流程（1/3）：準備考題

  1. UDM/ARPF產生認證向量，算出 CK'、IK' 取代 CK、IK
  2. UDM把 AV' 回給 AUSF（收到 SUCI 時附上 SUPI）
  3. AUSF產生 EAP-Request/AKA'-Challenge 送給 SEAF

運作流程（2/3）：轉送與作答

  1. SEAF原封不動轉給 UE，附上 ngKSI、ABBA
  2. UE（USIM + ME）驗證 AUTN，算出 RES，推導 CK'、IK'
  3. UE → SEAF → AUSF回傳 EAP-Response，SEAF 透明轉送

運作流程（3/3）：驗證與金鑰

  1. AUSF比對 RES 與 XRES，成功就通知 UDM
  2. AUSFEMSK → KAUSF → KSEAF，送 EAP Success 與 KSEAF（與 SUPI）
  3. SEAF / UE轉送 EAP Success；雙方各自推導 KAMF

白話解釋

5G-AKA 的分公司會先看一眼答案的指紋；EAP-AKA' 的分公司只是郵差，考卷和答卷都密封往返。

總公司親自批改，合格就寄回「合格通知」（EAP Success）和門禁卡（KSEAF）。

常見考點（1/3）

  • EAP 三角色在 5G 是誰？peer = UE、pass-through authenticator = SEAF、EAP 伺服器 = AUSF
  • SEAF 角色有何不同？EAP-AKA' 只轉送；5G-AKA 用 HXRES* 初步比對
  • KAUSF 怎麼產生？EAP-AKA'：EMSK 最高 256 bits；5G-AKA：CK||IK + SN name

常見考點（2/3）

  • SN name 綁在哪？EAP-AKA'：CK'、IK'（AT_KDF_INPUT）；5G-AKA：RES* 與金鑰
  • 都有 increased home control 嗎？都有，AUSF 驗證成功後通知 UDM（§6.1.4.1）

常見考點（3/3）

  • 誰決定用哪一種？home network 業者；UE 與服務網路兩種都要支援
  • 支援 fast re-authentication 嗎？5G 不支援（Annex F.3）
