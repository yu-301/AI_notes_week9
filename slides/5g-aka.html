§6.1.3.2

5G-AKA 認證

手機與網路用 USIM 裡的長期金鑰互相認證，最後由 home network 親自確認結果，拜訪網路無法自行宣稱認證成功。

為什麼需要

  • 手機與網路要互相確認身分，並產生後續加密金鑰
  • 4G EPS-AKA：認證結果完全由拜訪網路的 MME 判定
  • home network 拿不到證據，可能被替不在場的用戶假登記
  • 5G-AKA：RES* 送回 home network，由 AUSF 最終確認（increased home control）

關鍵名詞

SEAF Security Anchor Function
在 AMF 裡，發起認證、初步比對
AUSF Authentication Server Function
home network 端做最終比對
ARPF Authentication credential Repository and Processing Function
在 UDM 裡，存 K、產生認證向量
RAND / AUTN Random Challenge / Authentication Token
隨機考題／證明考題真且新
HXRES* Hash of XRES*
標準答案的雜湊，給 SEAF 比對

認證向量數量可一次拿多組每次一組、不可預抓

運作流程（1/3）：發起與產生向量

  1. SEAF帶 SUCI（或 SUPI）與 SN name 向 AUSF 發起認證
  2. AUSF確認 SEAF 可用該 SN name，轉給 UDM/ARPF
  3. UDM/ARPFSIDF 解出 SUPI、選 5G-AKA，產生 RAND、AUTN、XRES*、KAUSF

運作流程（2/3）：出題與作答

  1. AUSF留下 XRES*，算出 HXRES*、KSEAF，只給 SEAF RAND、AUTN、HXRES*
  2. SEAF送 RAND、AUTN、ngKSI、ABBA 給手機
  3. UE（USIM + ME）驗證 AUTN 與 separation bit，算出 RES*、KAUSF、KSEAF，回傳 RES*

運作流程（3/3）：比對與確認

  1. SEAF比對 HRES* 與 HXRES*，不論結果都把 RES* 轉給 AUSF
  2. AUSF比對 RES* 與 XRES*、通知 UDM，成功才交出 KSEAF（與 SUPI）
  3. SEAF / AMF推導 KAMF、啟動 NAS SMC；UE 收到合法 SMC 才算成功

白話解釋

總公司寄給分公司一道考題和「標準答案的指紋」。你答完，分公司先比對指紋，再把你的答案送回總公司。

總公司親自對過標準答案，才把門禁卡（KSEAF）交給分公司，還會記下你在哪通過驗證；分公司想謊稱「他來過了」也騙不了總公司。

常見考點（1/3）

  • 和 EPS-AKA 最大差別？RES* 送回 home network，由 AUSF 最終確認
  • 為什麼 SEAF 只拿 HXRES*？能初步檢查，但無法偽造 RES* 騙 AUSF
  • 手機怎麼確認網路是真的？用 K 驗證 AUTN 的 MAC，再檢查 SQN 防重放

常見考點（2/3）

  • SN name 有什麼用？「5G:」+ SN Id，綁進 RES* 與金鑰，服務網路無法冒充別人（§6.1.1.3）
  • SQN 不同步怎麼辦？回 Authentication Failure 附 AUTS，經 AUSF 到 UDM 重新同步（§6.1.3.3）

常見考點（3/3）

  • RES* 比對失敗怎麼辦？用 SUCI → Authentication Reject；用 5G-GUTI → 改要 SUCI 再試（§6.1.3.2.2）
  • AUSF 確認後還要做什麼？用 ResultConfirmation 通知 UDM，供之後檢查註冊是否可信（§6.1.4.1a）
