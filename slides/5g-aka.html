§6.1.3.2

5G-AKA 認證

手機與網路用 USIM 裡的長期金鑰互相認證，最後由 home network 親自確認結果，拜訪網路無法自行宣稱認證成功。

為什麼需要

  • 手機與網路要互相確認身分，並產生後續加密金鑰
  • 4G EPS-AKA：認證結果完全由拜訪網路的 MME 判定
  • 漫遊時拜訪網路可謊稱用戶已認證，冒用身分或灌水帳單
  • 5G-AKA：最終由 home network 的 AUSF 確認（increased home control）

關鍵名詞

SEAF Security Anchor Function
在 AMF 裡，發起認證、初步比對
AUSF Authentication Server Function
home network 端做最終比對
ARPF Authentication credential Repository and Processing Function
在 UDM 裡，存 K、產生認證向量
RAND / AUTN Random Challenge / Authentication Token
隨機考題／證明考題真且新
HXRES* Hash of XRES*
標準答案的雜湊，給 SEAF 比對

比較項目4G EPS-AKA5G-AKA
誰判定成功MME 自行判定SEAF 初步、AUSF 最終確認
拜訪網路拿到XRES（明文）只有 HXRES*

金鑰綁定KASME 綁定 SN IDRES*、KAUSF 綁定 SN name

運作流程（1/2）：準備考題

  1. SEAF帶 SUCI/SUPI 與 SN name 向 AUSF 發起認證
  2. AUSF確認 SEAF 可用該 SN name，轉給 UDM/ARPF
  3. UDM/ARPF解出 SUPI，產生 RAND、AUTN、XRES*、KAUSF
  4. AUSF留下 XRES*，算出 HXRES*、KSEAF，只給 SEAF RAND、AUTN、HXRES*

運作流程（2/2）：作答與確認

  1. SEAF送 RAND、AUTN、ngKSI、ABBA 給手機
  2. UE（USIM + ME）驗證 AUTN，算出 RES → RES*，推導 KAUSF、KSEAF
  3. SEAF比對 HRES* 與 HXRES*，相符後把 RES* 轉給 AUSF
  4. AUSF比對 RES* 與 XRES*，成功才交出 KSEAF（與 SUPI）

白話解釋

總公司寄給分公司一道考題和「標準答案的指紋」。你答完，分公司先比對指紋，再把你的答案送回總公司。

總公司親自對過標準答案，才把門禁卡（KSEAF）交給分公司，分公司想謊稱「他來過了」也騙不了總公司。

常見考點（1/2）

  • 和 EPS-AKA 最大差別？home network 的 AUSF 做最終確認
  • 為什麼 SEAF 只拿 HXRES*？能初步檢查，但無法偽造 RES* 騙 AUSF
  • 手機怎麼確認網路是真的？用 K 驗證 AUTN 的 MAC，再檢查 SQN 防重放

常見考點（2/2）

  • SN name 有什麼用？綁進 RES*、KAUSF，只對該服務網路有效
  • SQN 不同步怎麼辦？回 Authentication Failure 附 AUTS，重新同步（§6.1.3.3）
  • AUSF 確認後還要做什麼？通知 UDM 認證結果 待查證：§6.1.4
