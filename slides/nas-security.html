§6.4

NAS 安全機制

UE 與 AMF 之間的 NAS 訊號同時有完整性與加密保護，並靠 NAS COUNT 防止重放攻擊。

為什麼需要

  • NAS 是 UE 與 AMF 間的控制訊號：註冊、移動管理、身分查詢
  • 被竄改、偽造或重放，就可能被降級或冒充網路下指令
  • 需要完整性、機密性、重放保護，端點是 UE 與 AMF
  • 5G 另外處理多重接取（§6.4.2）與初始訊息保護（§6.4.6）

關鍵名詞

NAS Non Access Stratum
UE 與 AMF 間的控制訊號層
NIA / NEA Integrity / Encryption Algorithm for 5G
128-bit 完整性／加密演算法
NAS-MAC NAS Message Authentication Code
附在訊息後的 32-bit 驗證碼
NAS COUNT NAS Count
OVERFLOW + SQN，防重放
NAS SMC NAS Security Mode Command
選演算法、啟動 NAS 安全

運作流程（1/2）：初始訊息與 SMC

  1. UE無上下文：初始 NAS 訊息只放 cleartext IEs
  2. UE有上下文：完整訊息加密放進 NAS container，整則做完整性保護
  3. AMF找不到上下文或驗證失敗，就發起主要認證
  4. AMF送出 NAS SMC：重播 UE 安全能力、選定演算法、ngKSI（只做完整性）

運作流程（2/2）：啟動保護

  1. UE驗證 SMC 並比對安全能力，通過就啟動 NAS 安全
  2. UE回 Security Mode Complete，必要時附完整初始訊息
  3. AMF開始下行加密，以完整初始訊息為準回應
  4. UE / AMF每則訊息算 NAS-MAC、加密；每個 NAS COUNT 只收一次

白話解釋

每份公文都裝進只有你和總務處（AMF）打得開的信封、蓋上印章（NAS-MAC）、寫上流水號（NAS COUNT），重複的流水號一律退件。

總務處回信時會把「你說你會用的鎖」再念一次，不一樣就代表中間有人動過手腳。

常見考點（1/3）

  • NAS 安全保護哪兩端？UE 與 AMF；UE 與 gNB 之間是 AS 安全
  • NAS COUNT 組成？16-bit OVERFLOW + 8-bit SQN，只傳 SQN
  • 為什麼不能隨便歸零？同金鑰同 COUNT 會重用金鑰流；新 KAMF 才歸零

常見考點（2/3）

  • 同時 3GPP + 非 3GPP 連同一 AMF？共用上下文，各自的連線 ID 與 NAS COUNT
  • 初始 NAS 訊息怎麼保護？明文只放 cleartext IEs，其餘加密進 NAS container

常見考點（3/3）

  • SMC 怎麼防降級？重播 UE 安全能力讓 UE 比對（§6.7.2）
  • 完整性可以改回 NULL 嗎？不行，啟用後直到上下文刪除（§6.4.3.2）
