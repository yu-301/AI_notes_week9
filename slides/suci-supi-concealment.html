§6.12

SUPI 隱藏與 SUCI

5G 用公鑰加密把用戶永久身分 SUPI 包成 SUCI，空中介面上不再出現明文 IMSI，讓假基地台抓不到你是誰。

為什麼需要

  • 2G～4G：網路認不出臨時身分時，手機會用明文回傳 IMSI
  • 假基地台（IMSI catcher）主動發出身分請求，就能收集附近手機的 IMSI
  • 拿到 IMSI 就能追蹤特定使用者的位置
  • 5G 目標：永久身分不再以明文出現在空中介面

關鍵名詞

SUPI Subscription Permanent Identifier
永久身分，常見格式為 IMSI
SUCI Subscription Concealed Identifier
SUPI 加密後的版本
5G-GUTI 5G Globally Unique Temporary Identifier
認證後網路分配的臨時身分
SIDF Subscription Identifier De-concealing Function
在 UDM 裡，持有私鑰、負責解開 SUCI
ECIES Elliptic Curve Integrated Encryption Scheme
ECDH 算共享金鑰 + 對稱加密的混合加密法

SUCI 長什麼樣

欄位內容加密？
SUPI TypeIMSI 或 NAI否
Home Network IdentifierMCC + MNC否
Routing Indicator導向正確的 UDM否
Protection Scheme ID0 = Null、1 = Profile A、2 = Profile B否
Home Network Public Key ID用哪一把公鑰否
Scheme Output臨時公鑰 + 加密 MSIN + MAC tag是

運作流程（1/2）：手機端

  1. 電信業者（事前配置）公鑰寫進 USIM，私鑰只放在 SIDF
  2. UE每次產生全新的臨時金鑰對
  3. UEECDH + KDF 推導出加密金鑰與 MAC 金鑰
  4. UE只加密 MSIN、附上 MAC，組成 SUCI 送出

運作流程（2/2）：網路端

  1. AMF/SEAF → AUSF → UDM依明文 MCC/MNC 把 SUCI 轉回 home network
  2. UDM 中的 SIDF用私鑰驗證 MAC、解出 SUPI，進行認證
  3. 認證成功後服務網路取得 SUPI 並分配 5G-GUTI

白話解釋

信封外只寫「請轉交台北總局」（MCC/MNC），收件人姓名封在只有總局打得開的內袋（加密的 MSIN）。

每次寄信都換新內袋（臨時金鑰），所以就算攔下兩封信，也看不出是同一人寄的。

常見考點（1/2）

  • 為什麼 MCC/MNC 不加密？服務網路要靠它知道該轉給哪個 home network
  • 為什麼每次 SUCI 都不同？每次用新臨時金鑰，達到 unlinkability
  • 誰能解開 SUCI？只有 home network UDM 裡的 SIDF

常見考點（2/2）

  • SUCI 由誰計算？USIM 或 ME，由 home network 業者決定
  • Null scheme 何時用？風險？沒配置公鑰、未認證緊急通話；等同明文
  • SUPI、SUCI、5G-GUTI 差別？永久身分／加密版本／認證後的臨時身分
